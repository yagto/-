## 怎么看

**直接双击 `index.html`。**

V2 不用 ES Module，全部是普通脚本 + `defer`，所以 `file://` 下能正常跑 ——
**不需要服务器，不需要打包，不需要生成第二个文件。**

> V1 那个"双击打开就没了交互"的坑，在 V2 从根上没有了。原因是 V1 用了 ES Module，
> 浏览器在 `file://` 下会拒绝加载模块，而 CSS 照常加载，于是排版还在、交互静默消失。
> V2 换成普通脚本 + `window.Resume` 命名空间，问题不存在了。

万一哪天脚本真的没跑起来，页面顶部会跳出一条黄色提示，而不是安静地少一半。

## 你只改这两个地方

### 1. 换配色 → `assets/css/theme.css`

**全站所有颜色只在这一个文件里定义。** 想换主色，改这几行就够：

```css
--c-primary:        #0284c7;   /* 主色：大字号、图标、边框、色块 */
--c-primary-ink:    #0369a1;   /* 深一号，给正文里的小字用（过 AA 对比度） */
--c-primary-bright: #38bdf8;   /* 亮一号，给背景色块用 */
--c-primary-soft:   #e0f2fe;   /* 极浅，给标签底色用 */
--c-primary-line:   #bae6fd;   /* 极浅，给分隔小圆点用 */
```

⚠️ **浅色主题下最容易犯的错，是拿亮天蓝当正文色。** 看着好看，实际读不清。
所以这里刻意分成两个"深"的天蓝：大字号用 `--c-primary`，正文小字用 `--c-primary-ink`。
换色的时候请保持这个分工。

### 2. 改内容 → `index.html` 和 `content/qa.js`

- **页面上的文字**都在 `index.html` 里，每个区块有注释标明是什么。
- **AI 分身的问答库**在 `content/qa.js` 里，格式说明写在该文件开头。

## 浮动面板怎么调 —— 「关于我」四块 + 「我能做什么」两块

**静止态**：四块只显示一个居中的大标题（18px），详情收成 0 高，不占位。

**点击后**（三步，按顺序发生）：
1. 那一块**向它的对角拓展**，其余三块缩小并被推向各自的角落
2. 标题**滑到左上角并缩小**（18px → 13px）
3. 详情内容**延后 130ms 展开并淡入** —— 刻意错开，避免两件事同时发生显得突兀

再点一下、点空白处、或按 Esc 都能收回。

**方向逻辑全在 CSS 里**（`layout.css` 的 `.panels` 段），JS 只负责切类名。
要调手感，改 `.panels` 上这四个变量就行：

```css
--focus-scale:  1.3;    /* 被选中那块的放大倍数 */
--recede-scale: 0.82;   /* 其余块的缩小倍数 */
--recede-x:     18px;   /* 其余块被横向推开多远 */
--recede-y:     14px;   /* 纵向 */
```

**★ 标题的移动靠绝对定位 + 过渡，不要改成 flex 对齐。**
`left/top` 可以参与过渡动画，而 `align-self` 这类属性是"跳变"的，
改了就变成瞬间闪一下，没有平滑移动。

**⚠️ 有一个地方极易搞反：`transform-origin`。**

它标记的是"固定不动的那个点"。要让**左上角**的块向**右下**生长，
锚点必须是它**自己的左上角**（`top left`）—— 写成 `bottom right` 就反了，
它会朝左上跑。

四块的锚点 = 各自所在的角：

| 块 | 位置 | transform-origin | 推开方向 |
|---|---|---|---|
| 1 | 左上 | `top left` | 左上 (-1,-1) |
| 2 | 右上 | `top right` | 右上 (+1,-1) |
| 3 | 左下 | `bottom left` | 左下 (-1,+1) |
| 4 | 右下 | `bottom right` | 右下 (+1,+1) |

手机上四块是竖排的，没有"对角"可言，所以**只缩放不位移**。
用 `@media (max-width: 719.98px)` 单独处理了。

加面板 / 减面板：往 `.panels` 里加删 `<button class="panel">` 即可。
但 CSS 里的 `nth-child(1..4)` 方向和锚点要一起改，否则新块方向会不对。

### 「我能做什么」的两块版

同一套组件，只多一个修饰类 `.panels--duo`。**JS 一行都不用改** ——
`panels.js` 会把页面上每个 `.panels` 各自接上，两组互不干扰
（点其中一组时，另一组的 document 监听会发现"点在我地盘外"，顺手把自己收起来）。

唯一不一样的是**让位方向**：

| | 四块版「关于我」 | 两块版「我能做什么」 |
|---|---|---|
| 宽屏（≥720px） | 向对角让（左上那块往左上跑） | **向左右让** |
| 窄屏（<720px） | 只缩放，不位移 | **向上下让** |

覆盖全写在 `layout.css` 的 `.panels--duo` 段，只改 `--rx` / `--ry` 和
`transform-origin`，其余手感（`--recede-scale` 等）继续继承。

**★ 两个数被特意调过，别随手改回去：**

- `--focus-scale: 1.16`（四块版是 1.3）。两块比四块宽得多，
  沿用 1.3 会横向溢出容器。
- 窄屏那条**必须重写 `transform`** —— 四块版在窄屏把位移去掉了，
  而 `.panels--duo.is-focused` 比 `.panels.is-focused` 多一个类、
  优先级更高，才盖得住它。

**内容目前是占位符**（`index.html` 的 `#skills` 那一屏），等设计好再填。

## 项目截图弹层怎么加

「做过什么」那屏的项目条目可以挂一个截图入口。
**入口和项目名排在同一行**（用 `.exp__head` 包起来），写法：

```html
<li>
  <span class="exp__head">
    <span class="exp__name">小程序游戏</span>
    <a class="exp__shots" href="assets/img/game-1.jpg"
       data-gallery="assets/img/game-1.jpg|assets/img/game-2.jpg"
       data-gallery-title="小程序游戏 · 开发截图">
      查看开发截图<span class="exp__shots-count">2 张</span>
    </a>
  </span>
  <span class="exp__meta">2026</span>
  <span class="exp__desc">……</span>
</li>
```

| 属性 | 作用 |
|---|---|
| `href` | **没 JS 时的退路** —— 点开直接看第一张原图 |
| `data-gallery` | 图片清单，用 `\|` 分隔，顺序就是显示顺序 |
| `data-gallery-title` | 弹层标题（可选） |

`.exp__head` 用 `flex-start` 而不是 `space-between` —— 按钮要紧跟项目名，
靠右对齐中间会空一大截，看着像两条不相关的东西。
`.exp__shots` 高约 40px，比 `--hit`(44px) 小：它是行内次级操作，
做满 44px 会把项目名那一行整个撑高，不值当。

`assets/js/gallery.js` 启动后会把点击接管成弹层。
**页面上任何带 `data-gallery` 的元素都能触发**，不限项目条目 ——
以后想给别处加图，照这个写法就行。

关闭方式四种：✕ / 点背景 / Esc / 点面板空白处。
打开时焦点移到关闭按钮，关闭后还回原来那个按钮 —— 键盘用户不会掉到页面底部。
弹层打开时会给 `<html>` 挂 `.gallery-open` 锁住背景滚动，
不然分屏吸附下弹层滚到底会带着整页一起动。

**★ 图片一定要压缩过再放。** 现在那两张是从 2560px 的截图缩到 1600px、JPEG 质量 88，
一张 255KB 一张 209KB。不缩的话单张 2MB 起 —— 手机上加载会很难看，
而且这个页面是给 HR 第一眼看的。

**★ 踩过一个坑，而且是致命的，别重犯：**

`.gallery` 上写了 `display: flex`，而 `[hidden]` 属性自带的 `display: none`
来自**浏览器默认样式表** —— 优先级最低，被作者样式直接盖掉。
于是弹层虽然 `hidden` 着，却照样 `position: fixed; inset: 0` 铺满全屏、
吃掉所有点击（`opacity: 0` 只是看不见，不是不挡道）。

表现是**整页都点不动** —— 不只是截图按钮，悬浮球、复制联系方式、
面板展开全部失效。作者样式想让 `hidden` 生效，必须自己补一条
`.gallery[hidden] { display: none; }`。

⚠️ **这个 bug 用程序化测试是发现不了的。** `element.click()` 绕过命中检测，
照样能触发事件，测出来一切正常。**验点击必须用真实鼠标，
或者 `document.elementFromPoint(x, y)` 看那一层最上面到底是谁。**

## 打印 / 存 PDF

页脚写着「按 Ctrl+P 可以打印成一份干净的 PDF」，这条**必须真的成立** ——
HR 看到合适的简历，第一动作就是存下来转发给用人部门。

打印样式在 `base.css` 的 `@media print` 段，做这几件事：

- 关掉 scroll-snap 和 scroll-behavior
- 隐藏全部界面零件（悬浮球 / 面板 / 进度条 / 圆点 / 精简按钮，
  以及「按 Ctrl+P」那句提示自己）
- `.reveal` **强制可见** —— 没滚动到的屏在屏幕上是 `opacity: 0`，
  不处理的话打出来是空白
- 每屏 `min-height: auto` + `break-inside: avoid`，大致一屏一张纸
- 去掉底色只留边框和文字；链接后面自动附上 URL

**★ 踩过一个坑，别重犯：面板在打印时必须展开。**

屏幕上面板是收起的（标题绝对定位居中、详情 `max-height: 0`），
而打印时 `html.js-ready` 仍然在，那套收起样式照样生效 ——
**打出来只有几个标题，内容全是空白。** 这就是当初那句提示被删掉的原因。

修法是在 `@media print` 里把它打回「无 JS 兜底形态」：
标题 `position: static`、详情 `max-height: none`，
另外脱掉 `.section__inner` 上的手机端缩放 `transform`。

**⚠️ 这块没办法用自动化测试验完整。** 调不起真实的打印对话框（会阻塞、拿不到结果）。
能做的只有：把 `@media print` 的规则提取出来强制生效、再读计算样式，
这能查出「内容空白」这类问题，但**纸张分页效果测不了**。
改完打印样式，请自己按一次 Ctrl+P 看预览。

## 三条硬约束（改的时候别破坏）

### 1. 关掉 JS，页面仍然必须是一份完整可读的简历

内容默认**可见**；动画是后加的增强层。只有 `main.js` 装配完成、给 `<html>`
加上 `.js-ready` 之后，CSS 才允许把初始态藏起来交给动画。
任何未捕获错误都会撤销 `.js-ready`，页面整体退回静态全可见。

**已实测确认**（做法：在控制台执行
`document.documentElement.classList.remove('js-ready')`，这等价于撤掉所有增强态）：

| 元素 | 无 JS 时 |
|---|---|
| 身份卡 / 经历 / 联系方式的正文 | 完整可见 |
| 「关于我」四块的详情 | **完整展开**（不是收起的） |
| 四块标题 | 常规排在左上角，不是居中的大标题 |
| 悬浮球、进度条、圆点 | 隐藏（没 JS 它们也没用） |

**⚠️ 这里踩过一次坑，别重犯：**
「关于我」四块的收起状态（`max-height: 0; opacity: 0`）最初写在了**无条件选择器**上，
结果 JS 一挂，那四组内容一个字都看不见 —— 直接违反本约束。
修法是把收起态挂到 `html.js-ready` 下面：**默认完整可见，JS 就绪后才切成交互形态**。
和 `.reveal` 是同一套思路。

**改这一屏的 CSS 时，务必重跑上面的自测。**

### 2. 任何一屏的内容都不能超出视口

分屏吸附用的是 `scroll-snap-type: y mandatory`。某一屏内容高于视口时，
用户**永远滚不到它底部** —— 滚到一半停下会被强制弹回屏首。

**宽屏和手机的处理不一样，这是刻意的：**

| | 宽屏（≥ 768px） | 手机（< 768px） |
|---|---|---|
| 某一屏超高时 | **整站关掉吸附**，退回普通长滚动 | **不关**。该屏变成屏内可滚动，其余屏照常吸附 |
| 为什么 | 宽屏上超高通常是意外（窗口压扁、缩放 150%），退回长滚动最稳 | 手机是"一屏一页"的主力场景，因为几屏偏高就整个关掉吸附，会变成"上下页拼成一张长图" |

手机端的具体做法（`layout.css` 的 `< 768px` 段）：

- 每屏 `height: 100dvh`，正好一屏
- 默认 `overflow-y: auto` —— 内容超高时屏内上下滑
- JS 判定装得下的屏打 `.is-fits`，切回 flex 垂直居中、`overflow: visible`
- **`overscroll-behavior` 刻意留默认值**：屏内滑到底要能"接力"切到下一屏，
  写 `contain` 会把这条路堵死

**⚠️ 手机端是「压缩排版 + 统一缩放」两道工序，缺一不可。**

第一道，排版收紧（`layout.css` 末尾的 `< 768px` 块）。
第二道，JS 算出统一缩放系数（`sections.js` 的 `guardOverflow`）。

**2026-10-15 重测**（做法：在页面里开一个 390px 宽的 iframe 加载 `index.html`，
读各屏 `.section__inner` 的自然高 —— 比手动改窗口可靠，能一次跑完多个高度）：

| 屏 | 自然内容高 | 说明 |
|---|---|---|
| 身份卡 | 671px | 加了照片和身份字段后 577 → 671 |

**⚠️ 三条「隐性成本」，加内容前务必先看：**

1. **照片是「半免费」的。** 它和姓名区并排，文字块本来就比它高，所以不额外占高度 ——

   占了那一屏的 54%。想加东西基本只能往面板下面挤。

3. **手机端两块经历卡片是「上下叠」的**，不像桌面端并排 ——
   所以「我的经历」里任何一条变长，都是 1:1 加到屏高上。
   10-15 那次改动（实习描述加长 + 在校加第三条）直接把这一屏从 572 推到 704，
   一家吃掉了全站 28px 的余量，把 740px 的手机推下了不缩放档。
   **桌面端不受影响**（两卡并排，279 / 279 是平衡的）。

**★ 三条别踩的坑：**

1. **手机端的排版收紧写在 `layout.css` 最后。**
   它覆盖的 `.panel` / `.exp` / `.contact` 基础样式都写在上面，同为单类选择器、
   优先级相同，靠的是"后写的赢"。放前面会被基础样式盖掉
   ——踩过一次，压缩规则写在前头，面板高度纹丝不动。

2. **缩放下限 0.7 不能再低。** 低于它正文字号掉到 11px 以下，手机上读不动了。
   宁可让那一屏退回屏内滚动。

3. **缩放必须所有屏共用一个系数，而且要么全上、要么全不上。**

   早期写法是"缩完装得下才给它上缩放"，结果最高那一屏被排除在外：
   别的屏都缩到 0.9，只有它还是 100%，翻到那儿就是明显大一号 ——
   **这个 bug 真的出现过**，表现是"其他页面正常缩小，唯独经历页面没能正常缩放"。
   现在所有屏共用同一个变换，个别缩完仍装不下的改打 `.is-tall`
   （保留缩放保证字号一致，另外放开屏内滚动保证内容不被裁）。

4. **图片加载完要重量一次高度。** `section` 的高度被钉死在 `100dvh`，
   所以"内部变高了"这件事 `ResizeObserver` 看不见（它盯的是 section 自己的尺寸）。
   二维码图在手机上有 108px 高，图没加载完时算出来的系数会偏大，
   结果最高那一屏永远差几像素。`sections.js` 里挂了 `load` 事件重新测量。

**这个方案的代价要心里有数**：手机上整页缩到约 0.71~0.87，正文从 16px 变成
11~14px。**想让它更大，根子在「经历」——它有 6 个条目带描述，约 1.3 屏的内容。**
要么把描述写短，要么把它拆成两屏。

另：`scroll-snap-stop: always` 在本项目里是**分情况**的 ——
宽屏段禁用（那一屏真超高时它会让底部永远滚不到），
手机端段启用（每屏已固定 100dvh，内容超高的部分走屏内滚动，
"不可达"的前提不成立；而它负责的正是"一次只走一页"）。
两边都有注释说明，改之前先读那段。

### 3. 宁可兜底，不可答错

**2026-10-15 起：先问真模型（DeepSeek），不行才用本地库。**

```
config.AI.KEY 有值  →  问 DeepSeek
没填 / 超时 / 报错 / 超过每人提问上限  →  回落本地问答库
本地库也没命中  →  兜底句
```

本地库不会删。它是安全网 —— API 欠费、网络不通、模型改版，
页面都还能接话，**永远不会变成一个点不开的按钮**。

下面这套匹配器（`ai.js` 第 1～5 节）现在只在模型不可用时上场。
它的设计取向是**答错比答不上来伤害大得多**，有六道保险：

1. `must` 硬门槛 —— 有一个词不命中就直接淘汰
2. `exclude` 排除词 —— 命中就淘汰，用来挡"话题对但问的不是这件事"
3. **至少命中一个话题词或别名** —— 只靠 boost 词（"什么/哪里/怎么"）不算数
4. `requireBoost` 意图闸门 —— 光有话题词不够，还得有意图词
5. 整句负面意图检测 —— 中文的否定常跟在词后面
6. 阈值 + 歧义拒答 —— 两条同分时系统自己知道没把握

第 2、3 条是补新条目时踩出来的：「你们公司在哪里」曾被"实习经历"抢走
（那句里连"实习"两个字都没有），「能实习多久」也被它当成在问实习经历。

改完问答库，务必自测：网址末尾加 `?debug=1`，控制台执行

```js
Resume.debug.batch(['问题1', '问题2', '问题3'])   // 只测本地库，不联外网、不花 token
Resume.debug.ask('他最擅长什么？')                 // 真问一次模型，会花 token
```

`batch` 只看匹配器，**误答率必须为 0**。漏答（该答的答不上来）可以接受，答错不行。

**但模型那边不受这套阈值保护。** 它答得准不准，靠的是 `content/persona.js` 里的
提示词约束（资料里没有就说不清楚、不吹捧、跑题就拉回来）。
每次改完提示词，拿这几个问题各试一遍 —— 它们是最容易翻车的：

- `他的 GPA 是多少？` → 资料里是「待补充」，**不能编**
- `帮我写一段快速排序的代码` → 跑题，**应该礼貌拉回求职**
- `他现在有女朋友吗？` → 资料里完全没有，**不能编**

## AI 分身：密钥在哪、怎么换

**密钥在 `assets/js/config.js` 的 `AI.KEY`。**

这违反了「密钥不进前端」的通则，是**刻意选的**。理由：静态站点没有服务端，
密钥只能跟着页面发出去 —— 任何打开开发者工具的人都能看到它。
换来的好处是整个项目不用维护任何后端，还是「双击就能跑」。

所以要守的纪律只有两条：

1. **这把钥匙单独设一个低额度**，别和其他项目共用；
2. **哪天要把额度调高，先换一把新钥匙。**

### 想改成走中转

`ai.js` 第 6 节的契约从第一天就没变过：

```js
ask(question, ctx) -> Promise<{ source, text, hit }>
```

把 `config.AI.ENDPOINT` 换成中转地址、`KEY` 清空，前端其余代码**一行都不用动**。
中转那边只需要：收下 `{ question }` → 加上密钥转发给 DeepSeek → 把 `{ answer }` 返回。

### 三个可以调的地方

| 想改什么 | 去哪 |
|---|---|
| 他答什么（资料、语气、边界） | `content/persona.js` |
| 模型 / 超时 / 每人提问上限 | `assets/js/config.js` 的 `AI` 段 |
| 模型挂了之后怎么接话 | `content/qa.js`（本地问答库） |

### 已实测确认的事实（2026-10-15）

- **DeepSeek 允许浏览器直接跨域调用** —— 用带 `Origin` 头的 `fetch` 实测拿到 401
  而不是 CORS 拦截。**这是整个方案成立的前提**；换成不允许 CORS 的模型服务商，
  静态页面就调不通，只能回到中转方案。
- 接口是 OpenAI 兼容格式：`POST https://api.deepseek.com/chat/completions`
- 模型名用 `deepseek-flash`（旧名 `deepseek-v4-flash` 已下线，会被转接到新模型）
- **思考模式默认是开的，且 effort 默认 high。** 回答「他是谁」用不上推理链，
  开着又慢又贵 —— 请求体里带了 `thinking: {type: 'disabled'}` 把它关掉。
- 价格很便宜：flash 输入 1 元 / 百万 token（空闲时段），
  一次提问的系统提示词约 1500 token，**算下来一次不到 1 分钱**。
